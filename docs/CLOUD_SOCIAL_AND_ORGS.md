# Lexa — شبکهٔ اساتید ابری + پنل دانشگاه/موسسه + اتاق استاد نسخهٔ ۲

## مشکل
سایت Pages و APK اکسپورت ایستا هستند (بدون /api) و دسکتاپ SQLite محلی دارد؛ پس اساتید/مطالب/دوره‌ها
یا دیده نمی‌شد یا هر دستگاه نسخهٔ خودش را داشت.

## راه‌حل
- همهٔ داده‌های اجتماعی در Supabase (جدول + RLS + RPC): `supabase/002_cloud_social.sql`.
- `src/lib/cloud-api/install.ts` فراخوانی‌های `/api/*` اجتماعی را روی همهٔ پلتفرم‌ها به `handlers.ts` می‌فرستد
  و همان JSON قبلی را برمی‌گرداند؛ صفحه‌ها تقریباً دست نخورده‌اند. خاموش‌کردن: `NEXT_PUBLIC_CLOUD_SOCIAL=0`.
- آپلود آواتار/کاور/لوگو در باکت عمومی `lexa-media` (مسیر `/api/cover/upload` که قبلاً وجود نداشت هم کار می‌کند).

## راه‌اندازی (یک بار)
1. کل `supabase/002_cloud_social.sql` را در SQL Editor پروژهٔ Supabase اجرا کن.
2. خودت را ادمین کن:
   `update public.lexa_profiles set role='admin' where id=(select id from auth.users where email='YOU');`
3. بیلد Z: `bun run build:apk`، `bash scripts/build-pages.sh`، دسکتاپ؛ چک‌لیست QA پایین.

## جریان‌ها
- استاد شدن: «دانشگاه‌ها و موسسه‌ها» ← درخواست حساب استادی ← تأیید در کنسول مدیر Lexa؛ یا دعوت یک سازمان فعال (با پذیرش، حساب استادی خودکار).
- پنل سازمان: درخواست پنل (pending) ← مدیر Lexa بعد از پرداخت: فعال، طرح، ظرفیت اساتید، تاریخ انقضا.
  مدیر پنل استاد را جست‌وجو و دعوت می‌کند (دعوت روی پروفایل استاد هم هست)، استاد می‌پذیرد؛ استاد هم می‌تواند درخواست عضویت بدهد.
  یک استاد عضو چند سازمان. مالک می‌تواند «مدیر پنل» تعیین کند. سمت، حذف عضو، تنظیمات و لوگو.
- انتشار به نام سازمان: در اتاق استاد (مطلب و دوره) «انتشار به نام» → در صفحهٔ سازمان دیده می‌شود؛ مدیر پنل می‌تواند از صفحهٔ سازمان بردارد.
- اطلاعات تماس و یادداشت مدیر در `lexa_org_private` (فقط مدیران پنل و Lexa).

## اتاق استاد نسخهٔ ۲ (`studio-editor.tsx`, `StudioWriteView.tsx`)
بخش‌های فشرده (فقط یکی باز)، درج + بین بخش‌ها، کشیدن‌ورها کردن، تکثیر، واگرد/ازنو، Ctrl+S، نوار قالب‌بندی
(فهرست، مراحل، کارت اصطلاح، اهداف، مهم/هشدار/ترفند/یادآوری)، نکته‌ها ردیفی، جدول خانه‌به‌خانه، انتخاب ماده از
کتابخانهٔ قوانین، تغییر نوع بخش، متن/نکتهٔ اختیاری برای همهٔ نوع‌ها، چک‌لیست انتشار با پرش به ایراد.
دوره: فهرست فصل/جلسه کنار صفحه و ویرایش فقط جلسهٔ انتخاب‌شده؛ آزمون و پیش‌نمایش در زبانهٔ جدا. قالب داده بدون تغییر.

## باز / بعدی
- محتوای قدیمی SQLite منتقل نمی‌شود (اگر محتوای واقعی هست، اسکریپت انتقال لازم است).
- درگاه پرداخت؛ فعلاً فعال‌سازی دستی توسط ادمین.
- دوره‌های خصوصی سازمان + فهرست دانشجویان، گزارش پیشرفت کلاس.
- پنل مدیریت سروری (آمار کاربران، بازخوردها) هنوز فقط وب/دسکتاپ.
- از audit: سینک کل-بلاب بدون نسخه (حذف یادداشت برمی‌گردد)، فید آپدیت امضانشده، رمز پیش‌فرض ادمین، فایل‌های زباله در ریشهٔ ریپو.

## QA (Z)
مهمان: کتابخانهٔ عمومی/اساتید/مطلب در APK و Pages باز شود. ورود ابری → حساب عادی؛ درخواست استادی؛ ادمین تأیید؛
مطلب و دوره با همهٔ المان‌ها؛ آپلود کاور/آواتار؛ کامنت، امتیاز، فالو، افزودن دوره به کتابخانه روی دستگاه دیگر.
درخواست پنل → فعال‌سازی → دعوت استاد → پذیرش → انتشار به نام سازمان → صفحهٔ سازمان. خروج از حساب ابری → مهمان.
