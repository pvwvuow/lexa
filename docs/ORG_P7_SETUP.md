# فاز ۷: کانکتور (Lexa از سرور مرکز می‌خواند)

طرح کلی در `docs/ORG_LEARNING.md` و راهنمای مسئول فنی مرکز در `docs/ORG_CONNECTOR.md` است. این فاز روی `006` تا `011` سوار است.

## چه چیزی اضافه شد
- `supabase/012_connector.sql`
  - `lexa_org_integrations`: نشانی HTTPS، قالب (JSON یا CSV)، نوع ورود، تطبیق فیلدها، زمان‌بندی، کلید داخلی. **رمز یا توکن فقط در Supabase Vault** است (`secret_id`) و هیچ RPC آن را برنمی‌گرداند، جز تابع فقط‌service برای اجرای تابع.
  - `lexa_org_integration_runs`: گزارش هر اجرا (تعدادها و کد خطا با شمارهٔ ردیف؛ ۱۸۰ روز).
  - RPCهای مدیر (aal2): فهرست، ذخیره، ثبت/حذف رمز، حذف، کلید تازه، گزارش اجرا. حداکثر ۵ اتصال برای هر مرکز. عوض کردن سرور (host) یا نوع ورود، رمز قبلی را پاک می‌کند تا رمز به سرور دیگری فرستاده نشود.
  - RPCهای فقط‌service: خواندن تنظیمات با رمز، انتخاب اتصال‌های سررسیده (با قفل ۲۰ دقیقه‌ای)، شروع و پایان اجرا، و `lexa_connector_bulk` که همان تابع‌های SQL فاز ۵ را صدا می‌زند و نمره و معدل را با منبع `connector` ثبت می‌کند.
  - برای هر اتصال یک کلید API داخلی (فقط `students:write`، `staff:write`، `status:write`) ساخته می‌شود؛ دانشجو و مدرس از همان مسیر API ساخته می‌شوند (ظرفیت، یکتایی نام کاربری، ورود اول). این کلید در تب API با نام `connector: …` دیده می‌شود.
- `supabase/functions/org-connector/index.ts`: `/test` (فقط نام فیلدها و تعداد ردیف، بدون مقدار)، `/run` (دستی، با حالت آزمایشی بدون ذخیره)، `/tick` (برای pg_cron). فقط HTTPS، همان host، بدون redirect، رد نشانی‌های خصوصی، ۲۰ ثانیه و ۵ مگابایت برای هر پاسخ.
- `src/lib/cloud-api/org-connector.ts` و `src/components/app/OrgConnectorPanel.tsx`: تب «کانکتور».
- `docs/ORG_CONNECTOR.md`: راهنمای سرور مرکز.

## کار تو (یک بار)
1. SQL به ترتیب تا `011` و بعد `supabase/012_connector.sql`. اگر خطای Vault داد: Database ← Extensions ← `supabase_vault` را روشن کن.
2. Secret تازه در Edge Functions: `LEXA_CRON_SECRET` = یک رشتهٔ تصادفی بلند (مثلاً `openssl rand -base64 36`). `LEXA_API_PEPPER`، `LEXA_SERVICE_KEY` و `LEXA_PUBLISHABLE_KEY` همان قبلی‌ها هستند.
3. Deploy: `supabase functions deploy org-connector --no-verify-jwt` (و `org-api` باید از فاز ۵ deploy شده باشد).
4. زمان‌بندی: Database ← Extensions ← `pg_cron` و `pg_net` را روشن کن، بعد در SQL editor (جای `<project>` و رمز را پر کن):
   ```sql
   select vault.create_secret('<همان LEXA_CRON_SECRET>', 'lexa_cron_secret');
   select cron.schedule('lexa-connector-tick', '*/10 * * * *', $$
     select net.http_post(
       url := 'https://<project>.supabase.co/functions/v1/org-connector/tick',
       headers := jsonb_build_object('Content-Type', 'application/json',
         'x-lexa-cron', (select decrypted_secret from vault.decrypted_secrets where name = 'lexa_cron_secret')),
       body := '{}'::jsonb, timeout_milliseconds := 120000);
   $$);
   ```
   هر ۱۰ دقیقه حداکثر ۳ اتصال سررسیده اجرا می‌شوند. اجرای دستی بدون این مرحله هم کار می‌کند.

## نکته‌ها
- کانکتور هیچ ردیفی را حذف یا معلق نمی‌کند؛ تغییر وضعیت فقط با گزینهٔ «وضعیت هم به‌روز شود» و حداکثر ۱۰۰ مورد در هر اجرا.
- محدودیت زمان Edge Function (حدود ۱۵۰ ثانیه در طرح رایگان): برای مرکزهای خیلی بزرگ هر بخش را در اتصال جدا بگذار.
- بررسی DNS نشانی‌های خصوصی را رد می‌کند، ولی اگر مرکز DNS خودش را عوض کند ممکن است بین بررسی و درخواست تغییر کند؛ نشانی از دست مدیر مرکز است و پاسخ فقط به فیلدهای تطبیق‌داده‌شده تبدیل می‌شود.
