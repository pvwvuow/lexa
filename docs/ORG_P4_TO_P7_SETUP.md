این سند ادامهٔ `docs/ORG_P1_SETUP.md` / `ORG_P2_SETUP.md` / `ORG_P3_SETUP.md` است.
منبع طرح: `docs/ORG_LEARNING.md`. توالی اجرای SQL تا امروز: `006 → 007 → 008 → 009 → 010 → 011`.

## ۱) SQL (فقط یک بار، در SQL Editor سوپاباس، به همین ترتیب)

1. `supabase/009_study_time.sql` — جدول زمان مطالعه + RPCهای ضربان و آمار (فاز ۴)
2. `supabase/010_org_api.sql` — کلیدهای API با Vault + ایدمپوتنسی + جداول کانکتور (فاز ۵ و ۷)
3. `supabase/011_comparison_report.sql` — تابع گزارش مقایسه (فاز ۶)

هر سه فایل «امن برای اجرای مجدد»اند. بعد از اجرا، نیازی به کار دیگری روی سوپاباس نیست —
هر دو Edge Function توسط خود Lexa از قبل دیپلوی شده‌اند:

* `org-api` (verify_jwt=false) — API رسمی هر مرکز با کلید + امضای HMAC
* `org-connector` (verify_jwt=true) — خواندن خوراک JSON سامانهٔ خود مرکز با حساب فقط‌خواندنی

## ۲) فاز ۴ — زمان مطالعه و «آمار من»

* فقط زمان **فعال** ثبت می‌شود: صفحه جلوی چشم + فعالیت کاربر در ۲ دقیقهٔ آخر.
* هر ۶۰ ثانیه یک ضربان می‌رود؛ قطعی اینترنت صف آفلاین دارد و بعد خودکار می‌ریزد.
* سقف ۱۲ ساعت در روز (سرور هم دوباره چک می‌کند)؛ رویدادهای نامعقول رد می‌شوند.
* منبع داده `lexa_study_sessions` است؛ رویداد ریز کلیک/حرکت ذخیره نمی‌شود (اصل حداقل داده).
* صفحهٔ **«آمار من»** در سایدبار (مسیر `#/mystats`) — نمودار روزانه ۳۰ روز + جمع‌ها.
* پنل مرکز: تب «دانشجویان و حساب‌ها» کارت «زمان مطالعهٔ فعال دانشجویان» را دارد (مدیر با نشست دومرحله‌ای).
* محرمانگی: طبق شرایط استفاده ادمین Lexa به زمان‌های ثبت‌شده دسترسی دارد؛ هر مرکز فقط دانشجویان رسمی خودش را می‌بیند.

## ۳) فاز ۵ — API لکسا

* کلید در پنل مرکز، تب «کلیدهای API» ساخته می‌شود؛ راز فقط یک بار نمایش داده می‌شود و در **Vault** ذخیره است.
* هر درخواست: `X-Lexa-Key` + `X-Lexa-Timestamp` + `X-Lexa-Signature = HMAC-SHA256(secret, ts + "." + sha256(body))`.
* نوشتن: `POST /v1/students | staff | classes | enrollments | grades` و `POST /v1/students/{ref}/status`.
* خواندن: `GET /v1/reports/study | grades | comparison`.
* `X-Lexa-Idempotency` پاسخ ۴۸ ساعت را برای همان کلید بازپخش می‌کند؛ `X-Lexa-Sandbox: 1` همه‌چیز را اعتبارسنجی و هیچ‌چیز را نمی‌نویسد.
* محدودیت: ۹۰۰ درخواست در ۵ دقیقه برای هر مرکز، ۵۰۰ ردیف در هر درخواست. ردیف تکراری با `external_id`/نام کاربری تطبیق و به‌روز می‌شود.
* سند کامل با نمونه‌ها: `docs/ORG_API_OPENAPI.yaml`.

## ۴) فاز ۶ — گزارش مقایسه

* تب «گزارش مقایسه» در پنل مرکز: انتخاب ترم و کلاس، مرز گروه‌ها قابل تنظیم (پیش‌فرض <۱ ساعت، ۱ تا ۱۰، >۱۰ ساعت).
* گروه زیر ۱۰ نفر هرگز نمایش داده نمی‌شود؛ خروجی فقط میانگین/میانه/اختلاف با بازهٔ اطمینان ۹۵٪ است.
* نسخهٔ کنترل‌شده با معدل قبلی (`lexa_org_prior_gpa` فاز ۳) به‌شکل همبستگی جزئی محاسبه می‌شود.
* نمودار پراکندگی بدون هویت دانشجو؛ و همیشه این جمله: «این مقایسه همبستگی است و به‌تنهایی اثر لکسا را ثابت نمی‌کند.»

## ۵) فاز ۷ — کانکتور

* تب «اتصال سازمان»: نشانی HTTPS خوراک JSON سامانهٔ خودتان + نام کاربری/رمز فقط‌خواندنی (رمز فقط در Vault).
* شکل خوراک دقیقاً مثل بدنهٔ API: `{"students":[…], "staff":[…], "classes":[…], "enrollments":[…], "grades":[…]}` (هر بخش اختیاری؛ آرایهٔ ساده = دانشجو).
* «اتصال آزمایشی» فقط وصل‌شدن را چک می‌کند؛ «اجرای هم‌اکنون» می‌خواند و با تطبیق شناسه به‌روز می‌کند؛ هر اجرا با آمار در گزارش می‌ماند.
* زمان‌بندی در پنل انتخاب می‌شود؛ اجرای خودکار زمان‌بندی‌شده نیازمند فعال‌شدن pg_cron روی پروژه است و فعلاً اجرای دستی/خارجی است.

## ۶) آزمون سریع بعد از SQL

1. وارد حساب کاربری شوید، ده دقیقه در درس‌ها مطالعه کنید → «آمار من» باید دقایق را نشان دهد.
2. در پنل مرکز (با MFA) تب «کلیدهای API» → کلید بسازید و با curl یک دانشجوی آزمایشی بفرستید (یا `X-Lexa-Sandbox: 1`).
3. تب «گزارش مقایسه» → کلاس و ترم انتخاب و گزارش را ببینید (تا وقتی نمره/زمان نباشد، پیام «زیر ۱۰ نفر» می‌آید — طبیعی است).
