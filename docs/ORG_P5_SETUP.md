# فاز ۵: API لکسا برای مراکز

طرح کلی در `docs/ORG_LEARNING.md` و مرجع کامل برای برنامه‌نویس سامانهٔ مرکز در `docs/ORG_API.md` است. این فاز روی `006` تا `009` سوار است.

## چه چیزی اضافه شد
- `supabase/010_org_api.sql`
  - `lexa_org_api_keys`: نام، دسترسی‌ها (scope)، فهرست IP اختیاری، انقضا، آزمایشی/واقعی، باطل‌شدن. **رمز کلید ذخیره نمی‌شود**؛ فقط یک salt و چند نویسهٔ اول هش آن برای شناسایی.
  - `lexa_org_api_idem` (Idempotency-Key، ۲۴ ساعت)، `lexa_org_api_usage` (محدودیت درخواست در دقیقه)، `lexa_org_api_log` (بدون بدنه، رمز یا دادهٔ شخصی؛ ۱۸۰ روز).
  - ستون `code` روی ترم‌ها (مثلاً `1404-1`) برای تطبیق با سامانهٔ مرکز.
  - RPCهای مدیر (aal2): ساخت، فهرست، باطل کردن یا «باطل بعد از N ساعت» برای چرخش، و فهرست درخواست‌ها.
  - RPCهای فقط-service برای تابع: بررسی کلید و IP، محدودیت، idempotency، و ثبت گروهی کلاس، ثبت‌نام، نمره و معدل قبلی با حالت dry run (همه چیز بررسی و بعد برگردانده می‌شود).
- `supabase/functions/org-api/index.ts`: خود API. امضای HMAC با timestamp (±۵ دقیقه)، کلید آزمایشی = dry run، ساخت حساب دانشجو و مدرس (مثل `org-auth`، رمز یک بار در پاسخ)، تغییر وضعیت، گزارش‌ها، `openapi.json`، و مسیر `/manage` برای ساخت و چرخش کلید از داخل اپ.
- `src/lib/cloud-api/org-api.ts` و `src/components/app/OrgApiPanel.tsx`: تب «API» پنل مرکز (ساخت کلید، نمایش یک‌بارهٔ رمز، چرخش، باطل کردن، آخرین درخواست‌ها).
- `docs/ORG_API.md`: مرجع API با نمونهٔ bash، Python و Node.

## چرا رمز کلید جایی ذخیره نمی‌شود
رمز هر کلید = `HMAC(LEXA_API_PEPPER, شناسهٔ کلید + salt)`. pepper فقط در تنظیمات Edge Function است و salt در پایگاه داده. پس با لو رفتن پایگاه داده به‌تنهایی هیچ کلیدی لو نمی‌رود، و سامانهٔ مرکز هم رمز را نمی‌فرستد؛ فقط با آن امضا می‌کند. عوض کردن pepper همهٔ کلیدها را یک‌جا باطل می‌کند.

## کار تو (یک بار)
1. SQL به ترتیب: `007`، `008`، `009` (اگر هنوز اجرا نشده‌اند) و بعد `supabase/010_org_api.sql`.
2. در Supabase ← Edge Functions ← Secrets یک مقدار تازه بساز: `LEXA_API_PEPPER` = یک رشتهٔ تصادفی دست‌کم ۳۲ نویسه (مثلاً خروجی `openssl rand -base64 48`). آن را جایی امن نگه دار و در ریپو نگذار.
   `LEXA_SERVICE_KEY` و `LEXA_PUBLISHABLE_KEY` همان‌هایی هستند که برای `org-auth` گذاشتی (همهٔ تابع‌ها مشترک می‌بینند).
3. Deploy: `supabase functions deploy org-api --no-verify-jwt` (سامانهٔ مرکز نشست Supabase ندارد؛ تابع خودش همه چیز را بررسی می‌کند).

## سیم‌کشی برای Z
1. **OrgView**: تب «API» فقط برای مالک، مدیر پنل و ادمین Lexa با `<OrgApiPanel orgId={org.id} />`. اگر نشست aal2 نیست همان پیام «ورود دومرحله‌ای» که بقیهٔ تب‌ها نشان می‌دهند.
2. هیچ route تازه‌ای در `handlers.ts` لازم نیست (اپ مستقیم RPC و `/functions/v1/org-api/manage` را صدا می‌زند).
3. `tsc`، build، QA پایین، نسخهٔ تازه.
